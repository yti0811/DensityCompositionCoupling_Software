# Density–Composition Coupling Software

Python scripts for *Density–composition coupling in compressible interfacial adsorption of a two-state soft solute*.

## Setup

Keep all numbered `.py` files in one folder. Install the required packages:

```bash
python -m pip install -r requirements.txt
```

## Notes

- Run all commands from the directory containing the numbered scripts. This is especially important because script 01 writes relative to the current working directory, whereas several downstream scripts locate inputs relative to their own files.
- Keep all 14 scripts together. Scripts 10–14 use the model functions in script 01; scripts 11 and 12 also import script 10, and script 13 calls script 12.
- Script 11 reads the roots CSV generated by script 10. Script 13 reads the coarse-grid CSV generated by script 12.
- Scripts 10–14 produce CSV files without figures. Scripts 10–13 default to `quick` mode. This is exploratory stationary-solution calculation, not the production multistart/global-screening procedure. Specify `--mode certified` explicitly for production screening. Script 14 always uses the production solver and has no `--mode` argument.
- The opening docstring in script 13 describes a certified workflow, but its actual command-line default in this release is `quick`. The explicit command below selects `certified` without changing the script.
- “Certified” names the implemented numerical candidate search, residual, stability and branch-selection checks. It is not a mathematical proof of global minimality.
- Preserve full-precision CSV files and record the Python and package versions used. Two-grid changes are numerical diagnostics, not rigorous error bounds. Near-zero adsorption differences should not be assigned a physical sign solely from a rounded CSV value.

## Revision-test configurations and SI mapping

The references below use the SI section and table numbering in the supplied second-revision manuscript. Script numbers are execution identifiers, not table numbers: **script 14 corresponds to SI Sec. S4.7 and Table S7**.

| Script | SI location | Configuration |
|---|---|---|
| 10 | S2.4, Table S1 | Three density stiffnesses; common wall scales 0.1, 1.0 and 1.5; baseline L=20 and dz=0.05; grid/domain checks enabled |
| 11 | S2.4, near-zero adsorption paragraph | Three stiffnesses × three verified interaction offsets × two spacings × two domains = 36 evaluations |
| 12 | S4.6, Table S6 | A, B, C and X; 12 conditions each; L=20 and dz=0.05; production screening |
| 13 | S4.6, Table S6 and two-grid comparison | Repeat all 48 conditions at L=20 and dz=0.025; compare with script 12 |
| 14 | S4.7, Table S7 | Separate runs at L=20 with dz=0.05 and dz=0.025; A, B and C |

Here `L` and `dz` are expressed in the numerical length units used by the model, with the default wall range equal to one; they correspond to the reduced domain length and grid spacing reported in the SI.

### Script 10: finite-wall crossover

```bash
python 10_finite_wall_crossover_refined.py \
  --mode certified \
  --kappas 5,20,50 --scales 0.1,1,1.5 \
  --chi-min 0.10 --chi-max 0.17 --chi-count 15 \
  --root-xtol 1e-7 --L 20 --dz 0.05 \
  --convergence --output revision_10
```

The baseline roots are calculated at L=20 and dz=0.05. With `--convergence`, the script additionally recalculates roots at dz=0.025 with L=20, and at L=30 with dz=0.05. Its default L=12 and dz=0.2 are not the baseline settings reported for the SI crossover audit.

Outputs:

- `revision_10/finite_wall_crossover_points_refined.csv`: sampled points and numerical diagnostics.
- `revision_10/finite_wall_crossover_roots.csv`: roots, brackets, statuses and convergence comparisons.

Check `status`, the mode, and the convergence fields. The three wall scales and three stiffnesses should give nine successful root records. Do not substitute quick-mode roots when reproducing a production-mode audit.

### Script 11: 36-evaluation near-crossover audit

**AUTHOR DRAFT — this subsection requires the three interaction offsets from the original 36-run calculation before publication.** The supplied SI states the number of interaction values but not their exact offsets. The command below fixes the run count; it does not establish that the published numerical bounds have been reproduced until the original offsets and reference roots are verified.

Script 11 constructs each interaction value as the input crossover root for the selected stiffness and wall scale plus an entry in `--offsets`. The original values can be recovered from the `offset_from_crossover` column of the audit CSV or from the original command line. The reference roots are read once from the specified roots file and are held fixed while the grids and domains are varied.

Set `SI11_OFFSETS` to the three verified comma-separated values. For an exact replay, use the corresponding production roots CSV and verify that its root-generation settings match the original audit. The proposed SI-matched grid/domain settings below are dz=0.05/0.025 and L=20/30; confirm these against the original 36-run record too.

```bash
# Set SI11_OFFSETS to the three values verified from the original audit.
# This guard intentionally prevents execution with an unspecified value.
: "${SI11_OFFSETS:?Set the three verified comma-separated offsets first}"

python 11_weak_wall_adsorption_sign_audit.py \
  --mode certified \
  --roots revision_10/finite_wall_crossover_roots.csv \
  --kappas 5,20,50 --wall-scale 0.1 \
  --offsets="$SI11_OFFSETS" \
  --dzs 0.05,0.025 --Ls 20,30 \
  --zero-tolerance 1e-9 --output revision_11
```

This specification gives 3 × 3 × 2 × 2 = 36 evaluations. The unmodified defaults give 3 × 5 × 3 × 2 = 90 evaluations and therefore describe a broader audit. Supplying the explicit options changes the requested run configuration, not the model or solver code.

Outputs:

- `revision_11/adsorption_sign_convergence_points.csv`.
- `revision_11/adsorption_sign_convergence_summary.csv`.

Check the requested and successful evaluation counts, the offsets, root values, `mode`, residuals and stability diagnostics. The absolute `1e-9` threshold is a reporting convention, not a numerical error bound. The manuscript's statements about the approximately `4.2e-11` maximum magnitude and `1.5e-11` variation refer to the reported audit configuration; they should not be transferred to a different choice of offsets without recalculation.

### Scripts 12 and 13: sensitivity and two-grid comparison

```bash
python 12_parameter_sensitivity_analysis.py \
  --mode certified --states A,B,C,X \
  --L 20 --dz 0.05 --error-floor 1e-9 \
  --output revision_12

python 13_sensitivity_grid_convergence.py \
  --mode certified --subset all \
  --reference revision_12/parameter_sensitivity_all_states.csv \
  --L 20 --dz 0.025 --output revision_13
```

Each state includes one baseline and 11 perturbed conditions. Thus the 48-condition audit contains four baselines; the 36 A–C conditions contain three baselines and 33 perturbed conditions. Script 13 runs script 12 on the finer grid and compares the results with the specified reference CSV.

Key outputs:

- `revision_12/parameter_sensitivity_all_states.csv`: coarse-grid conditions, results and diagnostics.
- `revision_13/fine_grid/parameter_sensitivity_all_states.csv`: fine-grid results used for the Table S6 response ranges and baseline column.
- `revision_13/grid_convergence_comparison.csv`: condition-by-condition comparison.
- `revision_13/grid_convergence_summary.csv`: state-level summaries of the two-grid changes.

Check that both files have 48 rows, both runs use `certified`, and the bulk/regular status fields are acceptable. The resolved response's relative grid change in script 13 uses the coarse-grid response magnitude as its denominator. The `adsorption_relative_error` column is the weak-wall error as a fraction; multiply by 100 to express it as a percentage. Near-zero entries with suppressed relative errors must not be counted as ordinary resolved-sign observations.

### Script 14: excess grand potential on two grids

Run the unchanged script twice with distinct output folders:

```bash
python 14_excess_grand_potential.py \
  --states A,B,C --L 20 --dz 0.05 \
  --output revision_14_dz005

python 14_excess_grand_potential.py \
  --states A,B,C --L 20 --dz 0.025 \
  --output revision_14_dz0025
```

Each folder contains `excess_grand_potential_comparison.csv`. Using different folders preserves both grids; repeating runs into the same folder would replace the earlier CSV.

- The dz=0.025 CSV supplies `gamma_ex_I`, `gamma_ex_II` and `delta_gamma_ex` for the numerical columns of **Table S7**.
- The dz=0.05 CSV supplies the production-grid differences quoted in Sec. S4.7 and the reference for the **Grid change** column.
- Both runs use the same functional, reservoir, wall and production solver. The dz=0.05 default is intentional and is not an error in the script.
- Script 14 writes the single-grid quantities and diagnostics. It does not automatically calculate a comparison between two separate invocations.

For each state, calculate the reported grid change as

```text
Grid change (%) = 100 * abs(delta_gamma_ex[d z=0.025] - delta_gamma_ex[d z=0.05])
                      / abs(delta_gamma_ex[d z=0.05])
```

The spaces in `d z` above are only descriptive notation. Use the CSV column `delta_gamma_ex`, not the adsorption column `adsorption_difference`. An optional read-only comparison command is:

```bash
python - <<'PY'
import csv
from pathlib import Path

def read(folder):
    with (Path(folder) / 'excess_grand_potential_comparison.csv').open() as f:
        return {r['state']: r for r in csv.DictReader(f)}

coarse = read('revision_14_dz005')
fine = read('revision_14_dz0025')
for state in ('A', 'B', 'C'):
    assert coarse[state]['status'] == fine[state]['status'] == 'ok'
    c = float(coarse[state]['delta_gamma_ex'])
    f = float(fine[state]['delta_gamma_ex'])
    print(state, 'coarse=', c, 'fine=', f,
          'grid change (%)=', 100 * abs(f-c) / abs(c))
PY
```

The SI comparison is approximately:

| State | dz=0.05: delta_gamma_ex | dz=0.025: delta_gamma_ex | Grid change (%) |
|---|---:|---:|---:|
| A | -3.503729e-8 | -3.501434e-8 | 0.0655 |
| B | -2.350900e-5 | -2.348546e-5 | 0.1001 |
| C | -3.831441e-5 | -3.825855e-5 | 0.1458 |

Calculate the percentages from the full-precision CSV values, not these rounded entries. Check `bulk_class`, `caseI_bistable`, `caseII_bistable`, `caseII_boundary`, the residual/eigenvalue columns, the local energy-gap diagnostics and the arithmetic discrepancy. These checks support the reported numerical comparison but do not provide a rigorous global-minimum certificate.
